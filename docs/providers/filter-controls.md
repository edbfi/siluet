# Provider filter controls

## D4 · Explicit filter preference on media submissions

Siluet’s default for optional provider content filtering is off. The request rules here define how Siluet is to send that preference with every image and video submission once a provider’s wire setting is known. This includes models whose individual manuals omit the field. For the ordinary JSON generation routes, the default outgoing values are Poyo’s nested `input.enable_safety_checker: false` and ToAPIs’ top-level `disable_nsfw: false`. Look up additional controls by provider, route, content type, exact model and operation. This index describes evidence for field acceptance and effect. Its model lists do not restrict which requests carry the preference.

Apply D4 according to the output the creator requested. A request to create or edit an image or video carries the preference. Omit D4 from Midjourney Describe (returns text), Sora character creation (returns a reusable character task ID), and PoYo Omni Moderation (returns a moderation assessment). A subsequent Sora request to generate a video using the character carries D4. These rules apply even when the operations share a submission endpoint. [Midjourney Describe](https://docs.toapis.com/docs/en/api-reference/images/midjourney/describe), [Sora character creation](https://docs.toapis.com/docs/en/api-reference/videos/sora2/create-persona), [PoYo Omni Moderation](https://docs.poyo.ai/api-manual/moderation-series/omni-moderation)

For ordinary generation requests, always include the provider’s boolean above. If the model also documents an independent NSFW off switch, include that switch alongside the boolean. Encode a shared field once. On ToAPIs Gemini Official, send the top-level boolean and the nested threshold for the sexually explicit category. Acceptance of the combination is unverified. D4 omits entries for other harm categories. It also omits person-generation controls and reduced-only fields such as `moderation` and `metadata.safety_tolerance`, leaving their behavior to the provider. A reduced setting cannot satisfy an off request.

For ToAPIs image and video generation or edit submissions with a JSON object body, Siluet also sends top-level `disable_nsfw: false` on specialized routes and follow-up generation actions, including Seedance final renders with `draft_task_id`. This is Siluet’s outgoing convention. Acceptance and effect remain unknown wherever the operation’s contract omits the field. On a submission using a different body format, the provider spec must establish the field encoding or record a coverage gap. Uploads, status reads and result downloads do not create a generation and carry no D4 setting.

A closed model schema can conflict with the owner’s observation that Poyo accepts the field across models. Record both, and preserve any actual rejection on the original attempt. Receiving a task ID confirms acknowledgement only. Siluet never silently strips the preference and repeats a paid submission. [Offline request examples](filter-request-examples.json)

Source review dated 2026-11-21. The [PoYo inventory](poyo/catalog.md) and ToAPIs [image](toapis/images.md) and [video](toapis/videos.md) inventories hold the complete model and operation lists. This index records the public request contracts. Account and channel availability, effective filtering, and output behavior remain unverified.

## PoYo.ai

The unified `POST /api/generate/submit` takes JSON. The controls below belong under `input`. The indexed English model manuals and the pinned catalog (`v1-c89a8585107f`, 2026-11-19) agree on the media IDs exposing `enable_safety_checker` or `moderation`. Neither source defines `enable_safety_filter`, `disable_nsfw`, or a different media alias for these controls. The Chinese model manuals expose the same control names. The unified envelope supplies no provider-wide filter field. [Unified OpenAPI](https://docs.poyo.ai/openapi.json), [English index](https://docs.poyo.ai/llms.txt), [Chinese index](https://docs.poyo.ai/_llms/zh.txt), [pinned catalog](https://github.com/PoyoAPI/poyo-devtools/blob/747e5d75319585d66396a3c05bd1b97d9390ce74/artifacts/capability-catalog.json)

### Reduced moderation and gaps

- `gpt-image-2.6-flare` and `gpt-image-2.6-sunburst` take `input.moderation` as a string for text generation and reference or mask edits. The enum is `"auto"` (default) or `"low"` (less restrictive). There is no off value. These closed input schemas exclude a separate checker switch. [Flare](https://docs.poyo.ai/api-manual/image-series/gpt-image-2-6-flare.json), [Sunburst](https://docs.poyo.ai/api-manual/image-series/gpt-image-2-6-sunburst.json)
- **Schema rejection.** The PoYo inventory links the model-level contracts. Closed `input` schemas (`additionalProperties: false`) without any mapped field include GPT Image 2.5 Flare, Sunburst and Fixed, GPT Image 2.6 Fixed, Ideogram 4.5/4.6 generation and edit and Vector 1.0, Kling Image 4.0 and Long, MAI 2.6/2.7 including Flash, MiniMax H3 Image, and Nano Banana 2.1. Video contracts include Flux 3 Max’s three IDs, HeyGen Avatar 6 and Turbo, Kling 1.6 Standard/Pro, Kling 4.0 and Flash, OmniHuman 2.0, PixVerse V6 Max, Seedance 2.5 and Flash, and the video translation, background removal and upscaling tools. The image translation manual also closes `input`. The pinned catalog closes the inputs for `gemini-omni-1.1-flash` and `gemini-omni-1.2-flash` without a filter field. Ideogram 4.6 generation and edit additionally document an unsupported-field error. [Model-level references](poyo/catalog.md), [pinned catalog](https://github.com/PoyoAPI/poyo-devtools/blob/747e5d75319585d66396a3c05bd1b97d9390ce74/artifacts/capability-catalog.json), [Ideogram 4.6](https://docs.poyo.ai/api-manual/image-series/ideogram-v4-6), [Ideogram 4.6 Edit](https://docs.poyo.ai/api-manual/image-series/ideogram-v4-6-edit)
- **Undocumented.** Remaining inventory entries have no documented off mapping. An omitted field in an open schema or a missing per-ID contract leaves acceptance and effect unknown. `omni-moderation-latest` is a separate review operation with its own task, even though it shares the submission path. [Model inventory](poyo/catalog.md), [Omni Moderation](https://docs.poyo.ai/api-manual/moderation-series/omni-moderation)

- **Fallback routing and type rejection.** For the Seedream 5.5 and Wan 3.0 contracts, ToAPIs consumes the field itself and sends no such parameter upstream. Only literal JSON `false` enables fallback eligibility. `true`, omission or `null` leaves fallback disabled. A string such as `"false"` or other non-boolean, non-null value returns HTTP 400. Mainland China users and China sales regions always have fallback disabled. The Seedance and MiniMax guides do not specify this fallback contract. [Seedream 5.5](https://docs.toapis.com/docs/en/api-reference/images/seedream-5.5/generation), [Wan 3.0](https://docs.toapis.com/docs/en/api-reference/videos/wan3.0/generation)
- **Asset review.** Some Seedance channels automatically review reference media before generation. The guides specify the review and its rejection outcomes separately from `disable_nsfw`. Only the non-Flash 2.5 model offers a draft and final render. Its guide expressly exempts final renders from asset review. It provides no filtering guarantee for the final output. [Seedance 2 review](https://docs.toapis.com/docs/en/api-reference/videos/seedance-2/generation#asset-review), [2.5 review](https://docs.toapis.com/docs/en/api-reference/videos/seedance-2-5/generation#asset-review), [2.5 Flash review](https://docs.toapis.com/docs/en/api-reference/videos/seedance-2-5-flash/generation#asset-review), [1.0 review](https://docs.toapis.com/docs/en/api-reference/videos/doubao-seedance/generation#asset-review), [1.5 review](https://docs.toapis.com/docs/en/api-reference/videos/doubao-seedance-1-5/generation#asset-review), [content errors](https://docs.toapis.com/docs/en/api-reference/errors)
- **Documented model conflict.** MiniMax H3 Image warns against applying other image models’ parameters or defaults. Its guide omits `disable_nsfw`. D4 still includes the boolean on this ordinary JSON route. Record the warning before submission and treat any actual rejection as the result of that attempt. [MiniMax H3 Image parameter limits](https://docs.toapis.com/docs/en/api-reference/images/minimax-h3-image/generation#unsupported-parameters)
- **Other routes and encodings.** No off mapping is published for Gemini Omni Standard/VIP JSON `POST /v1/videos` or the Official Omni interaction parameters, the Midjourney JSON action family (including image edits and video), the Grok and Sora follow-up routes, or Sora character creation. JSON extension by source URL has its own `POST /v1/videos/extend` path and also lacks a documented switch. Multipart uploads have their own routes and fields. MiniMax H3 Image excludes multipart generation and Grok Video 1.5 says some channels reject multipart binary uploads. The reviewed docs supply no multipart encoding for any filter field. [Omni Standard](https://docs.toapis.com/docs/en/api-reference/videos/gemini-omni-flash/generation-1-1), [Omni Official](https://docs.toapis.com/docs/en/api-reference/videos/gemini-omni-1.1-flash-preview-official/generation), [Midjourney](https://docs.toapis.com/docs/en/api-reference/images/midjourney/generation), [Grok Extend](https://docs.toapis.com/docs/en/api-reference/videos/grok-imagine-video-official/extend), [Sora Remix](https://docs.toapis.com/docs/en/api-reference/videos/sora2/remix), [Sora Character](https://docs.toapis.com/docs/en/api-reference/videos/sora2/create-persona), [image upload](https://docs.toapis.com/docs/en/api-reference/uploads/images), [MiniMax H3 Image](https://docs.toapis.com/docs/en/api-reference/images/minimax-h3-image/generation#unsupported-parameters), [Grok Video 1.5](https://docs.toapis.com/docs/en/api-reference/videos/grok-video-1.5/generation)
