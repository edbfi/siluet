# PoYo.ai model and operation inventory

Snapshot reviewed 2026-11-21. Compare API model IDs exactly, including case and slashes. The same marketing family may expose several submission IDs. A single ID can also infer its operation from supplied media. The marketplace and task directory organize discovery around families and overlapping capabilities. [Image overview](https://docs.poyo.ai/api-manual/image-series/overview), [video overview](https://docs.poyo.ai/api-manual/video-series/overview), [marketplace](https://poyo.ai/models), [task directory](https://poyo.ai/tasks)

The public discovery contract documents anonymous category listing, model search and model details at `/v1/catalog/categories`, `/v1/catalog/models` and `/v1/catalog/models/{model_id}`. List results are paginated. The catalog exposes input/output schemas and billing information per ID. The counts below use the published PoYo Devtools snapshot and the individual English OpenAPI files linked from the docs index. They describe public evidence on those surfaces. Availability on a creator’s key remains unverified. [Capability Catalog OpenAPI](https://docs.poyo.ai/integrations/capability-catalog.json), [PoYo CLI](https://poyo.ai/cli), [documentation index](https://docs.poyo.ai/llms.txt)

The English OpenAPI index contains **74 image IDs** and **86 video IDs**, plus four media tools and one music-to-video workflow. The **2026-11-19** snapshot (`v1-c89a8585107f`) lists **76 image IDs** across four image-related categories and **82 IDs** across four video-related categories. Those video categories include two media tools. Two translation IDs and one music-to-video ID bring the snapshot's media total to **161**. 156 IDs occur in both surfaces. [Pinned PoYo snapshot](https://github.com/PoyoAPI/poyo-devtools/blob/747e5d75319585d66396a3c05bd1b97d9390ce74/artifacts/capability-catalog.json)

Each row lists the exact IDs and the fields in that manual’s `input` schema. “Required in schema” lists unconditional JSON Schema requirements. The operation column records additional mode rules. Fields under “Additional” can be required or forbidden in a particular mode. Follow the linked manual for the full enum, bounds, defaults and nested properties. Where PoYo publishes a broad family schema, use the corresponding example and parameter notes for the chosen ID.

## Kling Image 4.0

- `kling-4.0-image` requires a nonblank `prompt` of up to 50,000 characters. Text mode omits `image_urls`. Image mode takes 1–10 ordered URLs for `@Image1` and later references. Each source can be up to 30 MB, must be at least 300 px on both axes, and must have a width-to-height ratio of 0.4–2.5. Image mode can add up to seven `kling_elements`. Each contains 2–4 `element_input_urls` in frontal-first order and is addressed as `@Element1` and so on. The combined count of reference images and elements is at most ten. Defaults are `size: "auto"`, `resolution: "2K"`, and `enable_sequential: false`. The manual lists ratios `16:9`, `9:16`, `1:1`, `4:3`, `3:4`, `3:2`, `2:3` and `21:9`, and resolutions 2K, 4K and 8K. Independent `n` is 1–9 with default 1. Sequential `n` is 2–10 with default 4, and the PNG files preserve series order. [Image manual](https://docs.poyo.ai/api-manual/image-series/kling-4-0-image), [Kling guide](https://poyo.ai/hub/kling-4-0-image-api-guide)
- `kling-4.0-long-image` requires the same kind of `prompt` and returns one tall PNG. `skill: "webpage"` is the default and accepts optional `style_image_url` and `subject_image_url`. `skill: "ecommerce"` requires 1–3 product `image_urls` and accepts `length` of `short`, `medium` or `long`, defaulting to medium. Choose `1K` (default, 1024 px wide) or `2K` (2048 px wide). Height follows content. [Long-image manual](https://docs.poyo.ai/api-manual/image-series/kling-4-0-long-image)

## Differences that affect implementation

- Shared endpoint fields have model-specific meanings. Kling Image 4.0 uses `size` as an aspect ratio. GPT Image 2 can use custom dimension strings. Seedream 5.0 Lite accepts size presets, strings or width/height objects. The unified OpenAPI illustrates a 20,000-character prompt and `n` up to 4. Kling Image 4.0 documents up to 50,000 characters and up to ten sequential outputs. [Unified OpenAPI](https://docs.poyo.ai/openapi.json), [Kling Image 4.0](https://docs.poyo.ai/api-manual/image-series/kling-4-0-image), [GPT Image 2](https://docs.poyo.ai/api-manual/image-series/gpt-image-2), [Seedream 5.0 Lite](https://docs.poyo.ai/api-manual/image-series/seedream-5-0-lite)
- Media ordering and field names vary. FLUX 3 puts each positioned anchor in `keyframes` with `frame_index` and `image_url`. Kling 1.6 uses separate `start_image_url` and `end_image_url`. Kling 4.0 uses ordered `image_urls` for frames and dedicated reference arrays for other media. Seedance separates frame and reference inputs. [FLUX 3](https://docs.poyo.ai/api-manual/video-series/flux-3), [Kling 1.6](https://docs.poyo.ai/api-manual/video-series/kling-1-6), [Kling 4.0](https://docs.poyo.ai/api-manual/video-series/kling-4-0), [Seedance 2.5 Flash](https://docs.poyo.ai/api-manual/video-series/seedance-2-5-flash)
- Result count, type and metadata matter. Kling can return an ordered PNG series. Ideogram Vector returns SVG. Seedream Layer Decomposition returns a base image and PNG layers with structured position and text information. Check the model contract for file roles and supplemental fields. [Kling Image 4.0](https://docs.poyo.ai/api-manual/image-series/kling-4-0-image), [Ideogram Vector](https://docs.poyo.ai/api-manual/image-series/ideogram-vector-1-0), [Seedream Layer Decomposition](https://docs.poyo.ai/api-manual/image-series/seedream-5-5-layerize)
- Resolve documentation mismatches before enabling a capability. The snapshot gives some translation models extra fields beyond their manuals. Seedream 5.0 Pro marks `size` and `resolution` required while the same manual supplies defaults. The tables retain the published schema requirements. Per-account entitlement, effective defaults where sources conflict, and actual runtime enforcement are unresolved.
