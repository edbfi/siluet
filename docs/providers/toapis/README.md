# ToAPIs image and video evidence

Reviewed 2026-11-21 against ToAPIs' public reference and English documentation sitemap. The provider dates its pricing-catalog snapshot 2026-11-10. Its headings say 41 image and 54 video models, while the tables contain 43 and 54 rows respectively. Two Grok Imagine Video IDs sit in the image table with both endpoint tags, and two IDs in the text table have an image endpoint tag. Count the rows for reconciliation and use each model's endpoint reference for operation coverage. The [image inventory](images.md) and [video inventory](videos.md) include documented IDs outside the snapshot as well as catalog rows with unresolved contracts. [Public model catalog](https://docs.toapis.com/docs/en/api-reference/models), [documentation sitemap](https://docs.toapis.com/sitemap.xml).

`GET /v1/models` defaults to text. Filters `type=image`, `type=video` and `type=all` expose the catalog available to a particular API key. IDs and `supported_endpoint_types` are discovery hints. Key restrictions, user group, channels, and pricing configuration affect the returned list. Availability, pricing, and cross-endpoint use remain unverified for any specific account or region. [List Models](https://docs.toapis.com/docs/en/api-reference/chat/list-models).

## Submission and retrieval

| Stage | Documented contract |
| --- | --- |
| Authentication | Bearer API key. Generation docs generally use `https://toapis.com` or `https://toapis.cn` for mainland China. Some image guides use `api.toapis.com` or `api.toapis.cn`. The Public Account API has a separate `/api/v1` contract and authorization model. [Quick Start](https://docs.toapis.com/docs/en/quickstart), [Public API access](https://docs.toapis.com/docs/en/api-reference/account/overview), [GPT Image 2.6 Official](https://docs.toapis.com/docs/en/api-reference/images/gpt-image-2.6-official/generation). |
| Local file input | Bearer-authenticated multipart `POST /v1/uploads/images`, `/v1/uploads/videos` or `/v1/uploads/audios`. Required `file`, optional `purpose` defaults to `generation`. Observe `success` and read `data.url` as the fetchable reference URL. The upload record also supplies `data.id`, MIME type and size in bytes. Image JPG/PNG/WebP/GIF up to 30,000,000 bytes, video MP4/WebM/MOV up to 50 MB, audio MP3/WAV/M4A up to 50 MB. Model limits on type, size, dimensions, duration and count still apply. [Image upload](https://docs.toapis.com/docs/en/api-reference/uploads/images), [video upload](https://docs.toapis.com/docs/en/api-reference/uploads/videos), [audio upload](https://docs.toapis.com/docs/en/api-reference/uploads/audios). |
| URL inputs | Model pages generally require retrievable public HTTP(S) URLs. Use the returned upload URL in the specific field for that model. The upload ID is for tracking. Inline base64 and local paths are excluded by the ordinary upload and generation guides. The upload references give no per-upload URL expiry or fetch-authorization contract beyond their public URL descriptions. Account retention defaults to 30 days and may shorten platform deadlines. [Image upload](https://docs.toapis.com/docs/en/api-reference/uploads/images), [request errors](https://docs.toapis.com/docs/en/api-reference/errors), [file retention](https://docs.toapis.com/docs/en/api-reference/account/files/get-retention). |
| Acknowledgement | Ordinary JSON `POST /v1/images/generations` and `POST /v1/videos/generations` typically return a top-level `generation.task` with the ToAPIs `id`, `model`, `status` and Unix-second `created_at`. Preserve the opaque ID and its query route. Most examples start at `queued`, GPT Image 2.5/2.6 guides show `pending`, and Gemini Omni Standard/VIP examples omit `progress`. Some accepted Seedance requests are still in asset preparation. [Vidu Q3 multi-model](https://docs.toapis.com/docs/en/api-reference/videos/vidu-ali/generation), [GPT Image 2.5 Official](https://docs.toapis.com/docs/en/api-reference/images/gpt-image-2.5-official/generation), [GPT Image 2.6](https://docs.toapis.com/docs/en/api-reference/images/gpt-image-2.6/generation), [Gemini Omni 1.1 Standard](https://docs.toapis.com/docs/en/api-reference/videos/gemini-omni-flash/generation-1-1), [Seedance 2 asset review](https://docs.toapis.com/docs/en/api-reference/videos/seedance-2/generation#asset-review). |
| Poll and classify | `GET /v1/images/generations/{task_id}` or `GET /v1/videos/generations/{task_id}`; ordinary tasks also accept `GET /v1/tasks/{task_id}`. Gemini Omni Standard/VIP, Midjourney and Sora character tasks have model-specific paths. Ordinary status values are `queued`, `in_progress`, `completed` and `failed`. Integer `progress` represents 0–100 when supplied. Failure examples use both 0 and 100, so terminal state comes from `status`. Docs do not establish monotonicity, an ETA, or the fraction of upstream work represented. HTTP 200 can contain `status: failed` with `error.code`, `error.message`, and optional `error.reason`. [Image status](https://docs.toapis.com/docs/en/api-reference/tasks/image-status), [video status](https://docs.toapis.com/docs/en/api-reference/tasks/video-status), [Vidu failure example](https://docs.toapis.com/docs/en/api-reference/videos/vidu-ali/generation#query-task), [errors](https://docs.toapis.com/docs/en/api-reference/errors). |
| Result retrieval | On ordinary completion read all `result.data[].url` entries under `result.type`, preserving documented item fields. Video items may include `format` and a requested `last_frame_url`. Some Seedance accounts receive upstream originals and optional per-item `fallback_url` and `fallback_last_frame_url` copies. Try the corresponding original first, then a copy if present and the original is inaccessible. Seedream layer output carries per-item layer metadata. Media download is a separate outcome from task execution. [Image status](https://docs.toapis.com/docs/en/api-reference/tasks/image-status), [video URL fallback](https://docs.toapis.com/docs/en/api-reference/tasks/video-status#seedance-original-and-fallback-urls), [Seedream 5.5](https://docs.toapis.com/docs/en/api-reference/images/seedream-5.5/generation). |
| Expiry | Ordinary status pages document 30 days and a Unix-second `expires_at` on completion. Use the returned timestamp where present. Seedance originals can become inaccessible independently of fallback availability. The docs give no guarantee of refreshing expired media URLs or reconstructing a missing copy. Midjourney documents expiring URLs without a duration in its action guide. [Image expiry](https://docs.toapis.com/docs/en/api-reference/tasks/image-status#resource-expiration), [video expiry](https://docs.toapis.com/docs/en/api-reference/tasks/video-status#resource-expiration), [account retention](https://docs.toapis.com/docs/en/api-reference/account/files/get-retention), [Midjourney best practices](https://docs.toapis.com/docs/en/api-reference/images/midjourney/best-practices). |

## Recovery and billing

- With a task ID, query the same task. For transient query errors, honor `Retry-After` and use bounded exponential backoff with jitter. ToAPIs recommends polling at intervals of at least 5–10 seconds with jitter and documents separate per-user submit/query buckets, independent of key count, with up to 100 IDs per batch query. Retrieval retries can use the existing result and any documented fallback. After a download failure, the accepted task and its known completion still stand. [Rate limits](https://docs.toapis.com/docs/en/api-reference/rate-limits/async-tasks), [video status](https://docs.toapis.com/docs/en/api-reference/tasks/video-status), [errors](https://docs.toapis.com/docs/en/api-reference/errors).
- After a timeout or `submission_unconfirmed`, ToAPIs documents `GET /v1/video/requests/{client_request_id}` under the same account, only if the supported video submission originally used `client_request_id`. Follow any returned `task_id`. Keep waiting in `submitting` or `unknown`. For this recovery flow, only `state=failed` with `error_code=submission_rejected` confirms rejection. A missing record can also mean expiry or an account mismatch. The reviewed model submit pages, including both Vidu Q3 pages, do not identify which routes accept this field. Its format, retention, and same-ID replay semantics remain unverified. With no confirmed job or rejection, preserve uncertainty and leave any new billable submission to the creator. [Errors and recovery](https://docs.toapis.com/docs/en/api-reference/errors#retries-and-request-recovery).
- `client_business_id` is a distinct correlation field. Seedance and Kling v4 explicitly allow querying by it on the video generations path, and Qwen Image allows it on the image generations path. The account task list can filter by it. The account task detail endpoint takes only a task ID. None of these lookup contracts promises duplicate suppression, exactly-once billing, or safe replay. Midjourney's best practices suggest backoff on network errors and 5xx, with no documented guarantee that a repeated billable POST is deduplicated. [Seedance 2](https://docs.toapis.com/docs/en/api-reference/videos/seedance-2/generation), [Kling v4](https://docs.toapis.com/docs/en/api-reference/videos/kling-4.0/generation), [Qwen Image](https://docs.toapis.com/docs/en/api-reference/images/qwen-image-3.0/generation), [account task list](https://docs.toapis.com/docs/en/api-reference/account/tasks/list), [account task detail](https://docs.toapis.com/docs/en/api-reference/account/tasks/get), [Midjourney retries](https://docs.toapis.com/docs/en/api-reference/images/midjourney/best-practices).
- Optional task webhooks require a configured HTTPS URL and signing secret on the token. A per-task callback must share that origin where supported. Signed terminal events use a distinct envelope, event ID, `data.task_id`, uppercase state, and string progress. Verify the raw body, deduplicate by event ID, and use polling if delivery is unavailable. ToAPIs retries deliveries with the same event snapshot and event ID. This delivery guarantee concerns webhooks. For the loopback scope in D1, polling can observe tasks without a public callback. [Task webhooks](https://docs.toapis.com/docs/en/api-reference/webhooks/task-webhooks).
- Prices may be per request, second, or token and may vary by resolution, channel, audio, reference media, and tool use. Some tasks reserve credits up front and reconcile after execution. The pricing catalog shows account or key configuration, and a price entry alone cannot guarantee availability or a final charge. The documented account catalog requires a system access token. A complete pre-submit quote contract across models and cost visibility after a lost acknowledgement remain unverified. Trust confirmed decimal strings `billing.credits` and `billing.cost_usd`. `pending` omits amounts, `settled` confirms actual cost, and `refunded` confirms a net zero charge. Generation state and settlement can change independently. Missing `billing` means unconfirmed. Top-level `usage` may expose charge basis and units, with some quantities omitted while pending. Seedance's nested upstream `generation.usage` has a different meaning. [Pricing catalog](https://docs.toapis.com/docs/en/api-reference/account/pricing/catalog), [actual cost](https://docs.toapis.com/docs/en/api-reference/account/pricing/actual-cost), [Seedance price lookup](https://docs.toapis.com/docs/en/api-reference/videos/seedance/pricing), [video status](https://docs.toapis.com/docs/en/api-reference/tasks/video-status).

Each scenario pairs provider-shaped HTTP data with local expectations for an offline test harness. Endpoint paths and JSON field names come from the linked references.
