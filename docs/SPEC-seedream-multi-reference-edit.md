# Seedream 5.5 multi-reference edit

**Milestone 3, third slice · Approved by the owner.** The owner can queue one Seedream 5.5 edit with up to ten ordered public image URLs on either connected provider and save one ordinary output to Gallery. This extends the [single-reference edit](SPEC-seedream-reference-edit.md) and inherits its access, validation, credential, submission, billing, tracking and Gallery rules. Files and mixed references, batches and requests with retries remain available for [offline Review](SPEC-image-studio.md). Layer decomposition stays deferred.

## Compose and review

Live edits require 1–10 valid public HTTP(S) URLs, one request and zero retries. Enforce these rules in the composer and at both `POST /image/review` and `POST /image/queue`. Validate every slot with the existing browser and server rules and derive each hostname from its URL. Keep exact duplicates (after trimming outer whitespace) in their separate slots for offline Review. Disable live Review and Queue until resolved, and identify the matching 1-based slots without echoing the URL. Both direct endpoints reject the duplicate draft. Distinct URL strings on the same host, including different signatures, are distinct slots. Preserve each trimmed string and its position, including escaping, query order, repeated parameters and fragments. Siluet performs no DNS lookup, media preview, fetch or upload of a reference. The provider determines reachability and media validity.

Show 1-based slot numbers in the composer and Review, with one hostname per slot. Show a unique draft-local reference label (for example, A or B) beside the URL field before staging. The owner may type a private name there such as “handbag” or “table” to associate the label with an image. The composer shows the name alongside its label. Editing the name changes only that private annotation. Review shows the ordered labels and hostnames. Keep the label and name with that reference through moves, removal of other slots and navigation to Settings and back. Replacing the URL starts a new identity and clears the old name. Labels and names live only in draft memory and never enter local POST bodies, provider requests, tokens, persisted data or logs. Provide keyboard-operable **Move up** and **Move down** controls with names that identify their slot. Disable moves at the ends, keep focus on an available control or the moved item itself and announce its new position. The visible order is the array order. Reordering leaves the prompt text as written so the owner can review any references to numbered images. In the composer and Review, tell Poyo.ai users they can refer to “image 1” and “image 2” in array order. For a multi-reference Poyo.ai edit set to Auto, explain that the provider determines framing and point to the fixed aspect ratios when framing matters. For ToAPIs, say the URLs go in the displayed order and the provider leaves numbered prompt references unspecified. In the outgoing preview, show one redacted placeholder per slot and keep the existing redaction of URLs in the prompt.

## Authorize and recover

Review says Queue sends the prompt and **every full URL**, including paths, queries with any signatures and fragments, to the selected provider. Apply the inherited upstream and fallback disclosures, retention details and warning that a recipient can retain a fetched copy after a signed link expires. Bind authorization to the exact ordered payload, owner, provider, credential revision, quote, sole attempt and version of the disclosures shown. Adding, removing, replacing or moving a reference invalidates prior Review and clears unknown-price acceptance. Changes Siluet can observe in the disclosed recipients or possible routes, disclosure text, quote or credential also require updated Review and a fresh Queue click before provider traffic. Apply this on first claim of an unused one-reference Review issued under the previous disclosure too.

Preserve the one-reference payload and the existing atomic claim. Identical replay of a claimed Review, including one from the previous slice, returns its original job across restart and terms changes. A changed payload or acceptance flag fails replay. Only the first valid claim can dispatch one complete edit POST. Preserve the existing distinction between confirmed rejection, acknowledged task failure and uncertain submission.

If a provider rejects or fails the edit because it could not use a subset of the references, treat that as an outcome for the whole edit. Use the existing safe mapped messages. ToAPIs may supply zero-based input indexes with raw error details, but does not guarantee them for this model. For the documented unreadable-reference reason on a matching failed task, say “The provider could not read one or more reference images.” This also applies to previously saved single-reference job records. Discard the raw details and leave the exact failing slot and cause unspecified. Siluet never drops a reference, refreshes a link, switches provider or submits again automatically. Save and status recovery use only the acknowledged task. [Poyo.ai error codes](https://docs.poyo.ai/api-manual/error-codes) · [ToAPIs error reference](https://docs.toapis.com/docs/en/api-reference/errors#task-failure-reason-lookup)

Keep the URLs and prompt transient under the inherited rules. Exclude reference hostnames, URL components, provider echoes and request bodies from job and Gallery records, filenames, logs, diagnostics and persistent browser storage. Durable replay uses the installation-keyed binding. Save only the verified provider-reported result, even when it shares a hostname with a reference.
