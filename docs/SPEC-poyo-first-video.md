# First Poyo.ai video · V1

**Approved 2026-11-22 (owner delegated to council + orchestrator).** A signed-in creator with only a Poyo.ai connection can review one H3 Max text-to-video request, queue it once and follow it in Jobs while Siluet saves the verified clip automatically. After restart they can play, seek, download or remove it offline. This is one model and operation under [D2](decisions.md#d2--full-image-and-video-model-coverage). Poyo Seedance 2.5 remains unavailable under D4 because its closed input schema omits the required field. [Seedance schema](https://docs.poyo.ai/api-manual/video-series/seedance-2.5.json)

| Duration | Integer 5–15 seconds | 5–10 seconds; widening toward the 15-second Save limit is a separate owner decision |

## Jobs and credits

Require successful HTTP, body `code: 200` and a `data.task_id` accepted by the existing task-ID validator (1–256 ASCII letters, digits, underscores or hyphens) without a conflicting error. Persist the ID immediately. The model guide shows initial `not_started` and `created_time`; the pinned catalog also illustrates an ID-only success payload inside `data`. For definite rejection, require an error envelope with no task evidence, an integer business code and either HTTP 200 or a matching HTTP error status. Recognize code 400 with validation_error, invalid_request_error, content_too_long_error or file_format_error as validation and content_moderation_error as filtering. Recognize 401 authentication_error, 402 insufficient_credits_error and 403 permission_denied_error as authorization, quota and permission respectively. A 403 leaves the saved balance-verified key intact. Unknown types and inconsistent envelopes stay uncertain. Display only local reason text and discard provider messages, including status error_message, before creating a UI or storage object. An HTTP or business 408/429/5xx, submission 404, timeout, conflicting or unreadable replies, and restart after claim without a durable outcome mean **May have been submitted**. Poyo documents lookup by provider task ID. Without that ID, direct the owner to provider history. Never retry submission, switch models, or drop D4. Apply the pre-claim and immediate pre-POST shared gate rules when [batch submission pacing](SPEC-live-image-batches.md#when-an-extra-post-is-allowed) is installed. If the serialized gate recheck immediately before the POST finds a cooldown, in one transaction record the job as unsent with zero POSTs and close any open wallet interval. Skip the after-balance read and comparison. Replay returns that same job. Once the POST starts, classify the response or loss of acknowledgement under the submission rules above. An exact Poyo limiter signature closes the gate while this single submission retains its uncertain outcome. Another attempt requires fresh Review and authorization. [Submit](https://docs.poyo.ai/api-manual/video-series/h3-max.md) · [Errors](https://docs.poyo.ai/api-manual/error-codes)

Read `GET /api/generate/status/{task_id}` with the original key revision. Require successful HTTP, body code 200 and the exact stored task ID before applying state, billing or files. Map `not_started`, `running`, `finished` and `failed` to waiting, running, completed and failed. Only a matching failed task confirms failure after acknowledgement. Poll every 2–5 seconds while healthy within the shared video window of ten minutes from acknowledgement. Coalesce poll, Refresh and Save reads across tabs, persist backoff, longer Retry-After and deadline across restarts, then offer manual Refresh. Preserve the last outcome on read errors. Use the video-specific persistent deadline independently of the two-minute image window. On reads, HTTP or business 401/403 pauses for access, 404 for a missing task, and 408/429/5xx applies temporary backoff, including business errors on HTTP 200. Pause on an unknown state, identity mismatch or key revision change. Warn in Settings before key changes that affect active jobs or unsaved results. [Video status and timing](https://docs.poyo.ai/api-manual/task-management/video-status.md) · [Existing Jobs](SPEC-first-saved-image.md#jobs-and-billing)

Use the existing bounded non-negative finite decimal amount parser for `data.credits_amount`. Label a valid amount as provider-reported task credits, with settlement finality unverified. Missing or invalid amounts stay unknown. Balance reads before submission and after a confirmed terminal outcome measure account-wide movement on one revision. A confirmed submit rejection or terminal task outcome reserves one bounded after-balance read. Keep its wallet interval open through that read, so any competing Poyo job marks both intervals as overlapping. Close it in the transaction recording, discarding or timing out the sample. ## Save and play offline

On a matching finished task accept exactly one `data.files` entry with `file_type: "video"` and a usable `file_url`. Missing files or a missing usable URL leave the job completed and show **Download failed**; mixed or multiple files show it as unsupported, with no Retry. The video guide gives three days from creation for content access, and the unified schema describes a 24-hour file URL, so Siluet saves the clip automatically on completion ([D9](decisions.md#d9--save-automatically)). An inaccessible link alone cannot confirm expiry. Retry download may obtain a usable URL only by rereading this same task under its cooldown. Poyo documents neither URL renewal nor a fallback URL. [Video result](https://docs.poyo.ai/api-manual/task-management/video-status.md) · [URL lifetime](https://docs.poyo.ai/api-manual/task-management/status.md)

Reuse the shared video verifier and authenticated local playback from [First saved video](SPEC-first-saved-video.md#save-and-play-offline). That contract governs transfer, sample accounting, verification, publication, removal and local serving on both providers. Poyo supplies a single delivery URL. Apply the full 60-second transfer budget and 64 MiB cap to that URL and its permitted redirects. Resolve and check each actual peer against the public HTTPS policy, send no credentials or cookies to media hosts, and accept only a complete identity-encoded response. Join duplicate saves and run one video Save at a time in the single runtime. Keep URLs transient and scratch files private.

Save verifies the stored file with the shared TypeScript structural checks and profile from First saved video (`verifyVideoFile` in `verify-video.ts`, under [D6](decisions.md#d6--verify-downloaded-video-structure-in-typescript)). Queue has no verifier gate. Poyo gives an MP4 example and optional file metadata. Actual container, streams and dimensions need local verification. Refusal leaves the completed job and available billing visible. Publish verified original bytes and one Gallery entry atomically. Serve owner-only GET, HEAD, byte ranges and attachments under the same-origin and private-cache rules. Provide keyboard-accessible inline playback, seeking and download after disconnect. Confirm local removal and retain job history. Keep prompts, keys, URLs, paths, raw responses and verification details out of logs, browser storage and durable job history.
