# First Seedream 5.5 reference-guided edit

**Milestone 3, second slice · Approved by the owner.** The creator supplies one public image URL and an edit prompt, reviews what the selected provider will receive and what it might charge, queues once, follows the job and saves the edited image for offline use. This extends [First saved image](SPEC-first-saved-image.md) on either connected provider. Its owner access, credential handling, billing, tracking and Gallery rules apply.

## Scope of a Queue click

Enable live editing for **exactly one URL, one ordinary output image, one request and zero retries**. One reference lets the creator authorize disclosure of a single asset and exercise the complete edit flow. The [next slice](SPEC-seedream-multi-reference-edit.md) extends the one-URL limit to ten ordered URLs. Files, mixed media, batches and retries keep the existing [offline Review](SPEC-image-studio.md) with the reason Queue is unavailable. Layer decomposition is deferred. Text-to-image keeps its existing path.

The browser and server apply the same public HTTP(S) URL rules. The server derives the hostname from the submitted URL. Reject userinfo, local names, non-public address literals and non-URL inputs. Validate syntax locally. During composition, Review and Queue, neither browser nor server resolves, previews, downloads, proxies or uploads the reference. The image must be accessible to the provider without the creator’s cookies or extra headers. A signed query can grant that access. The provider determines reachability, file format and byte size when it retrieves the image. Keep the link reachable through processing. Fetch timing, redirect handling and minimum remaining lifetime are unverified.

Review shows the reference hostname and explains that Queue sends the selected provider the prompt and **full URL, including its path, signed query and any fragment**. The provider and its upstream model services, including a fallback when the selected ToAPIs account and region are eligible, may process these inputs and fetch the image. A signed link may grant access until expiry. A recipient can keep a copy it has already fetched. [Poyo.ai privacy policy](https://poyo.ai/privacy) · [ToAPIs upstream processing](https://toapis.com/subprocessors)

Review’s outgoing request preview uses a reference placeholder and redacts URLs in prompt text. Send the exact validated URL spelling after outer whitespace trimming, preserving escaping, repeated parameters, query order and any fragment. The provider receives a fragment in the submitted JSON even though an HTTP fetch omits it. Keep API credentials on the local server and send them only to the selected provider’s API.

## Consent, recovery and retention

The server-issued Review binds the signed-in owner, edit operation, canonical provider payload including the exact URL, credential revision, quote, sole attempt and the exact version of the disclosures the creator saw. Those disclosures cover the full URL, all possible recipients and routes, retention, and copies kept after link expiry. On first use the server checks that version against the current terms. An outdated client must display the updated disclosures before it can authorize an edit. Changing only a signature on the same host changes the terms. Clear the previous Review and unknown-price acceptance on a draft change. At Queue, revalidate locally and require fresh Review and an intentional click for changed terms. Enforce the same scope at both direct POST endpoints. Reject stale or mismatched authorization before provider traffic.

Use the existing atomic claim and replay rules. Identical concurrent or later Queue requests for the same accepted Review return the original job, even after restart. A recognized rejection or an acknowledged task reporting failure can end an edit whose reference is inaccessible or expired. Show the mapped failure without echoing the URL or guessing that it expired. An ambiguous dispatch or missing durable acknowledgement shows **May have been submitted**. Check provider history before authorizing another attempt. Never refresh a signature, switch providers, strip a rejected option or resubmit automatically.

A Poyo.ai rejection with body code 400, `file_format_error` and no task ID is a validation failure. For ToAPIs, map `invalid_image`, `invalid_image_file` and `invalid_private_assets` to validation when an unambiguous request error has no task ID. A timeout, 408, 429, 5xx or contradictory response from ToAPIs remains uncertain at submission. After acknowledgement, if the matching ToAPIs task reports `failed` with `error.reason` of `reference_media_unreadable`, tell the owner the provider could not read the reference. Use the generic failure message for other failed tasks. Discard raw error details. ToAPIs lists expiry among the possible causes of unreadable media. Neither provider promises a specific code or time for detecting an expired reference. [Poyo.ai errors](https://docs.poyo.ai/api-manual/error-codes) · [ToAPIs request errors and task failure reasons](https://docs.toapis.com/docs/en/api-reference/errors)

Track the acknowledged task with the reviewed credential revision. Poyo.ai returns `data.task_id` with success code 200 and supplies the image in `data.files[].file_url`. ToAPIs returns `id` and supplies the image in `result.data[].url`. Use the existing status, expiry and billing rules. Use operation-neutral labels in Jobs and Gallery so previous jobs and new edits can share the existing records. Save downloads only the provider-reported result through the verified Gallery path. An expired result or failed download leaves the completed job available. Retry download reads the same task once and never submits ([D9](decisions.md#d9--save-automatically)). After saving, reopening the local result requires neither the reference nor a connected provider. [Jobs and Gallery contract](SPEC-first-saved-image.md#jobs-and-billing)

Keep the prompt and reference transient in the browser draft and the local Review/Queue POST bodies. Discard the draft on reload or sign-out. Durable replay protection uses an installation-keyed binding. Keep reference host, path, query, fragment, full URL, raw provider echoes and request bodies out of job and Gallery records, filenames, diagnostics, logs and persistent browser storage. Save only the verified output image and minimal job and Gallery metadata, including a bounded failure category when needed after restart.

## Acceptance before release

Use fresh provider fixtures and the built Bun app. Run the [development checks](../README.md#development). A billable verification requires separate express owner approval.

- On each provider, enter a URL with an escaped path and signed, repeated query parameters and a fragment. Review by keyboard at a narrow viewport. Check the hostname, full-URL and upstream disclosure, retention details, effect of link expiry, redacted JSON and dated edit estimate. Count zero external calls through Review, then exactly one edit POST to the selected provider with the original URL at the documented field. Assert zero reference fetches by Siluet through dispatch.
- Change just the query after Review. An old token paired with the new URL fails, consent clears and a fresh Review and click are required. Change only the retention disclosure version between Review and first Queue. Assert zero provider traffic until the new disclosure is shown and the owner consents again. Identical replay of an already claimed Review still returns its original job. Exercise changed price or credential revision, expired evidence and known standard price with unpriced fallback. Check signed-out, cross-origin, invalid URL, file, zero/multiple reference, batch and retry requests at the server. Rejected requests produce zero provider calls and zero jobs.
- Race duplicate Queue and replay after restart. Verify one job and one edit POST. Cover a documented rejection, an accepted job that later reports failure, and a lost provider acknowledgement. Exercise both providers’ documented validation errors and the ambiguous ToAPIs cases above. Have a failed ToAPIs task return `reference_media_unreadable` and echo the signed URL in `error.input_media_errors[].message`. Assert the operation-neutral Jobs label, safe failure message and zero further edit POSTs, including after a submission timeout.
- On each provider, track an acknowledged edit, let it save automatically, restart, disconnect and reopen the saved result. Have a reference and a distinct result share a host. Verify Save downloads the provider-reported result and reopening serves its bytes locally. Exercise an expired result, and a failed download followed by Retry download on the same task. Count zero further edit POSTs. Seed distinct reference-host, path, query, fragment and prompt markers and inspect local database records, logs, browser storage, job details and Gallery metadata for leakage across success, failure and restart.
