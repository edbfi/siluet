# Siluet ground-floor spec

Siluet's first deliverable is a working local build that a contributor can verify without a provider account. The [decision record](decisions.md) sets the product direction. The production milestones below build on this foundation.

## Acceptance criteria

1. A locked Bun install produces a strict TypeScript, Svelte 5 and SvelteKit 3 application using the Bun adapter. Panda CSS generates the page styles and the page exercises Ark UI for Svelte.
2. Starting the built application listens on loopback. Opening the root page identifies Siluet. A request to `GET /healthz` returns HTTP 200 and JSON `{"status":"ok"}`.
3. Type checking, Biome, focused tests and a production build pass. A Chromium smoke test opens the built server, checks the page and verifies its health response. The [README](../README.md) lists the local commands.
4. The initial PR runs the real `ci-ok` and `pr-policy` checks. CI installs Chromium before running the smoke test. Default-branch protections and dependency auto-merge follow the upstream [edbfi-ci onboarding order](https://github.com/edbfi/edbfi-ci/blob/main/SETUP.md).

The ground floor needs no persistence, credentials, model catalog or paid submissions. Milestone 1 replaces the status fixture with the protected Svelte studio.

## Production capability map

The baseline includes the releases through [#71](https://github.com/edbfi/siluet/pull/71) (2026-11-25) and the provider evidence recorded with each module spec. Siluet serves one creator on loopback, with their own credentials, explicit spending authorization and media saved in the private installation. [D1–D12](decisions.md) and the approved module specs set the scope.

### Shipped on the baseline

- Local password claim, sign-in and durable sessions, with owner data in embedded Turso through Drizzle. Provider Settings verifies and stores Poyo.ai and ToAPIs model keys independently. [Owner access](SPEC-owner-access.md) · [Image Studio](SPEC-image-studio.md)
- The server runs on Linux and macOS only and refuses any other platform before it touches the data directory. [D8](decisions.md#d8--linux-and-macos-only) ([#54](https://github.com/edbfi/siluet/pull/54))
- Seedream 5.5 reviews offline on both providers and queues text-to-image or ordinary edits. An edit takes 1–10 ordered references that mix public URLs and local JPEG or PNG files. Siluet sends the URLs without fetching them, uploads each file once in slot order, then submits one edit. Local files in other formats stay offline-Review only. Text-to-image and URL-only edits queue 1–5 requests with 0–3 extra attempts each; an edit with any local file queues one request with zero retries. Reordering invalidates unused Review. An identical replay of a claimed Review returns the original job or batch across restart. [First saved image](SPEC-first-saved-image.md) · [Multi-reference edit](SPEC-seedream-multi-reference-edit.md) · [Live batches](SPEC-live-image-batches.md) ([#35](https://github.com/edbfi/siluet/pull/35)) · [Local-file edit](SPEC-seedream-file-edit.md) ([#59](https://github.com/edbfi/siluet/pull/59)) · [Ordered file edit](SPEC-seedream-ordered-file-edit.md) ([#60](https://github.com/edbfi/siluet/pull/60))
- Siluet cleans every attached JPEG or PNG into a private copy in process as soon as it is attached, and Review previews the copy. The owner can turn cleaning off in Settings or during setup. An original must still be one still SDR JPEG or PNG. [Cleanup spec](SPEC-provider-media-cleanup.md) · [D7](decisions.md#d7--prepare-local-images-in-process) · [D10](decisions.md#d10--cleaning-is-a-standing-opt-out) ([#49](https://github.com/edbfi/siluet/pull/49), [#59](https://github.com/edbfi/siluet/pull/59))
- Jobs tracks durable acknowledgements, distinguishes uncertain submissions from failures, shows reported billing and supports an isolated Poyo.ai wallet comparison. Gallery verifies PNG and JPEG with a full decode, saves every completed result automatically and reopens, downloads or removes it offline. [First saved image](SPEC-first-saved-image.md) · [D5](decisions.md#d5--verify-gallery-images-before-saving) · [D9](decisions.md#d9--save-automatically) ([#58](https://github.com/edbfi/siluet/pull/58))
- The offline registry resolves the reviewed operations for the model picker, Review and Queue. [Media catalog](SPEC-media-catalog.md) ([#32](https://github.com/edbfi/siluet/pull/32))
- Poyo.ai Z-Image queues text-to-image and one public-URL edit with one attempt each, then saves the result. [Z-Image](SPEC-z-image.md) ([#34](https://github.com/edbfi/siluet/pull/34))
- ToAPIs Seedance 2.5 supports one text-to-video generation. Save checks the MP4 structure in TypeScript with no native tools, and saved clips play offline. [First saved video](SPEC-first-saved-video.md) ([#36](https://github.com/edbfi/siluet/pull/36), [#55](https://github.com/edbfi/siluet/pull/55)) · [D6](decisions.md#d6--verify-downloaded-video-structure-in-typescript)
- Poyo.ai H3 Max queues text-to-video as the representative of the Poyo.ai video family, with partial coverage: 5–10 s, 480p or 768p and six fixed ratios. Recovery and Retry download never send a second request, and the clip saves automatically. [Poyo.ai video family](SPEC-poyo-first-video.md) · [D2](decisions.md#poyoai-video-family) ([#57](https://github.com/edbfi/siluet/pull/57))
- ToAPIs Seedance 2.5 also animates a still from one public starting-frame URL, or guides a clip between distinct starting- and ending-frame URLs. Review names each frame by host, Queue sends one request with zero uploads, and the clip saves automatically. Poyo.ai keyframes stay unavailable under D4. [Seedance keyframes](SPEC-seedance-keyframes.md) ([#61](https://github.com/edbfi/siluet/pull/61))
- Queue, tracking and Save ship for both video families. Real provider clips from both families save with their C2PA content-credentials box kept, including Seedance's AAC priming; clips Save held outside the profile re-arm once; any still refused are held again. Other output shapes still fail closed until a real sample qualifies them. [D6](decisions.md#d6--verify-downloaded-video-structure-in-typescript) ([#65](https://github.com/edbfi/siluet/pull/65))
- Each video mode has a Save limit, its documented maximum output: 30 s for every Seedance mode and 15 s for H3 Max. Review states it, Queue stores it with the job, and Save accepts a clip up to the limit plus 1 s. A mode without one stays Review-only. Clips held for length before the upgrade re-arm once; any still refused are held again. [Per-mode limits](SPEC-video-save-limits.md) · [D6](decisions.md#d6--verify-downloaded-video-structure-in-typescript) ([#67](https://github.com/edbfi/siluet/pull/67))
- ToAPIs Seedance 2.5 edits a clip from one public source URL. Review names the source by host, states the edit's 30 s Save limit as the upstream maximum, unverified on this route, and warns that a longer source can be charged for an edit Gallery may not save. Queue sends one request with zero uploads, and the edit saves automatically when Gallery can keep it. [Source-video edit](SPEC-seedance-video-edit.md) ([#62](https://github.com/edbfi/siluet/pull/62))
- The owner can require an authenticator at sign-in and recover access on the host with the service stopped. [Owner authenticator](SPEC-owner-authenticator.md) ([#37](https://github.com/edbfi/siluet/pull/37))
- Each browser signs in with a key only Siluet's exact origin can use, so another local port receives no credential. [Browser key sessions](SPEC-browser-key.md) · [D1](decisions.md#browser-credential) ([#71](https://github.com/edbfi/siluet/pull/71))
- Every response from the server hook refuses framing by other pages, and saved media is served sandboxed. Startup refuses a data folder another user could swap, and the database files stay private to the owner. [Security review](decisions.md#security-review-2026-11-25) ([#69](https://github.com/edbfi/siluet/pull/69))

### D2 coverage acceptance

Start with the PoYo capability catalog at revision `747e5d7` (2026-11-19 UTC) and the ToAPIs public production catalog (2026-11-10 snapshot). Reconcile both with official model and endpoint docs, recording the revision or access date. ToAPIs documents `doubao-seedream-5-5` outside that snapshot. Its model-key inventory varies by account and group, so track account and region eligibility separately. [PoYo catalog](https://github.com/PoyoAPI/poyo-devtools/blob/747e5d75319585d66396a3c05bd1b97d9390ce74/artifacts/capability-catalog.json) · [PoYo docs index](https://docs.poyo.ai/llms.txt) · [ToAPIs catalog](https://docs.toapis.com/docs/en/api-reference/models) · [ToAPIs model-key inventory](https://docs.toapis.com/docs/en/api-reference/chat/list-models) · [Seedream contract](https://docs.toapis.com/docs/en/api-reference/images/seedream-5.5/generation)

The dated ledger in `docs/media-catalog.v1.json` is the canonical inventory for D2. Its reviewed offline operation registry is the source for the model picker, Review and Queue. Both use `(provider, exact model ID, route, operation)` as the key. Keep operation-specific contracts and fixture evidence with the provider adapters and focused tests. The ledger indexes evidence and gaps. Record discovery separately from verified support, credential access and pricing. Reconcile exact IDs and variants with generation, editing, keyframes, extension, layer decomposition and other documented media operations. Track input roles, limits and combinations, D4 compatibility, upload access and retention, request and acknowledgement, status and recovery, output types and expiry, and pricing and billing. Keep partial options and unqualified routes visible.

Include the text, caption and audio inputs of each documented image or video operation. ToAPIs Seedance 2.5 accepts audio-only and mixed-reference generation with `audio_with_roles` entries using `reference_audio`. For local audio, qualify the cleaner, upload route and model operation together. The ToAPIs public upload route lists MP3, WAV and M4A up to 50 MB and returns a reusable public URL. BytePlus lists MP3 and WAV with a 15 MB per-clip limit for its Seedance route. Verify the limits of the intended ToAPIs route before enabling a format. Before transfer, disclose access, retention, deletion and remaining unknowns. Bind verified bytes, order, roles and destination to Review. Fixtures check that the correct returned URL goes to the intended model in the reviewed role and order only after Queue consent. Locally rejected input or stale consent transfers zero bytes. Standalone audio and text model catalogs are outside D2. [Seedance reference limits](https://docs.toapis.com/docs/en/api-reference/videos/seedance-2-5/generation#reference-input-limits) · [Audio upload](https://docs.toapis.com/docs/en/api-reference/uploads/audios) · [Upstream limits](https://docs.byteplus.com/en/docs/ModelArk/seedance-2-5)

Give each row an evidence link and an explicit state:

- **Verified in Siluet**: a model with its own adapter and built-app tests. Each family's representative is one.
- **Contract-covered**: validated mechanically against a verified family under the [amendment](decisions.md#verification-by-contract-family).
- Otherwise **documented and pending**, **provider unsupported**, or **unknown** with the open question.

Track D4 separately as compatible, incompatible or unverified. The [D4 amendment](decisions.md#d4--optional-filtering-on-media-requests) adds two approved exceptions:

- provider-fixed filtering, with a per-Review acknowledgement
- an unconfirmed or undocumented field (ToAPIs, or an open Poyo.ai schema without it), with a Review disclosure

Both ship with the catalog engine. Since 2026-11-26 Siluet sends the field on every model whose schema does not forbid it, documented or not; closed schemas keep the acknowledged omit path. Neither path stops a verified or contract-covered row from counting toward coverage. Show unverified behavior and known conflicts in Review before Queue eligibility is evaluated. Preserve a provider rejection and the original request semantics. [D4](decisions.md#d4--optional-filtering-on-media-requests)
