# Seedream 5.5 edits with ordered files and public URLs

**Approved 2026-11-22; revised 2026-11-24 for R2 · Uploads 1.** A creator can queue one ordinary edit with 1–10 references in the order shown in Review. Each reference can be a public HTTP(S) URL or a privately staged JPEG or PNG, cleaned unless the owner turned cleaning off ([Sending originals](SPEC-provider-media-cleanup.md#sending-originals)). One setting applies to every file slot. Ship after [ordered URL edits](SPEC-seedream-multi-reference-edit.md), [single-file edits](SPEC-seedream-file-edit.md) and the [shared submit gate](SPEC-live-image-batches.md#when-an-extra-post-is-allowed). An upgrade restarts Siluet and retires every unclaimed stage, so an unused file Review answers `stale`. Claimed single-file jobs, their exact Queue replay, still-valid URL-only Reviews and Gallery items stay usable. This release authorizes one edit with one output and zero retries. Batches of file-backed requests need their own spend and hosted-copy terms.

## Jobs, cost and recovery

Jobs shows the total reference count, total file count and a fixed outcome per numbered file slot. Distinguish unsent, upload rejected, upload outcome unknown, and confirmed stored with usable or unusable receipt. Public URL slots require no upload. Record a fixed stop reason for a changed local stage, duplicate result URL, expired hosted link, provider cooldown or interruption before edit, with the relevant 1-based slots. Report the edit separately as unsent, rejected, potentially submitted, or acknowledged with its task ID. After interruption, classify the one in-flight phase using its durable boundary. Confirmed earlier uploads retain their recorded state, later uploads stay unsent. Even with every upload confirmed, a restart before the edit boundary leaves the edit unsent. Recovery never needs a raw hosted URL. An uncertain edit directs the creator to provider history. A new attempt requires fresh Review and restaging, with consent to additional copies and charges. Acknowledged tasks reuse ordinary tracking and verified Save.

Use one Poyo wallet interval from before the first upload through the bounded after-read, following single-file overlap and original-revision rules across all media. Unknown upload or edit outcomes suppress attribution across replacement keys. A known unsent edit may still have completed uploads. Keep upload charges unknown and show task charges only as reported. When no POST happened, close without a comparison. During live dispatch after a confirmed upload or an unambiguous first-upload rejection, follow the single-file bounded after-read for a definite stop. Check the original revision in the transaction that stores the after-sample and discard it on mismatch. Recovery closes a definite early stop without network traffic.
