# Clean local media before provider upload

**Image Studio capability · Approved 2026-11-22 for JPEG and PNG (Uploads 1). Video and audio remain proposed.** Staging a local file for a provider automatically prepares a clean copy. The creator keeps the original. Start with JPEG and PNG reference images. Qualify basic MP4 and MKV when a provider operation accepts them. The [Seedream URL edit](SPEC-seedream-reference-edit.md) sends a remote URL directly.

## From staging to submission

1. Preparation starts as soon as the creator attaches a file and needs no click or confirmation. Show preparation progress for each file. For an unsupported file, give a fixed reason and a next step, for example “HDR gain map. Choose an SDR JPEG or PNG.” Keep metadata values out of errors. If preparation, verification or a required tool fails, block Queue. Never send the original as a fallback.
2. Review identifies the provider, the ordered cleaned copies, and what survives cleanup. When preserving an embedded ICC profile, explain that its creator, copyright, creation date, device names, descriptions and private fields can survive. Explain that cleanup removes authorship and AI-source tags from supported EXIF, XMP and IPTC records and removes recognized embedded Content Credentials and that watermarks in picture or audio content survive. [C2PA embedding](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)
3. Before Queue, disclose whether uploading creates a reusable public link, who can use it, and what is known about access, retention and deletion. The provider issues the actual link after upload. An uploaded copy can remain accessible if the subsequent edit fails. ToAPIs documents a public URL for uploaded images and does not publish a single lifetime for accessible URLs. Preparing or reviewing makes zero external calls. [ToAPIs image uploads](https://docs.toapis.com/docs/en/api-reference/uploads/images) · [ToAPIs retention](https://toapis.com/data-retention)
4. Only the signed-in owner’s same-origin Queue authorizes transfer. Bind the verified bytes of each file in order, the owner, provider, credential revision, cleaning rules, access and retention disclosures, and request terms to Review. Enable a format and route only when the selected provider operation documents support for the cleaned output. Before first dispatch, recheck that eligibility, the binding and the provider’s input limits. A changed file, route, disclosure or credential, or an expired copy, requires fresh Review and a new click. Send exactly the verified bytes under an application-generated filename. Require HTTPS and provider-authorized public destinations for the entire transfer, including presigned destinations and redirects. Validate and connect to a public resolved address on every hop. Send API credentials only to authorized API destinations. Apply the approved operation’s spending and replay rules.
5. Use browser memory or private local scratch space. Release source bytes after preparation. Keep cleaned copies private to their owner and draft with a proposed 15-minute idle expiry. Release them after transfer, failure, removal, cancellation or sign-out. Protect active transfers and reclaim leftovers after interruption or restart. Keep media, original names and paths, metadata values and reusable upload URLs out of logs, durable job history and persistent browser storage. The cleaner creates no Gallery entry.

## Supported media

**Images.** Support single-frame SDR JPEG and PNG. Remove EXIF/GPS, XMP/IPTC including DigitalSourceType, comments, timestamps, thumbnails and editing history. Remove recognized JPEG APP11 JUMBF Content Credentials and PNG caBX. Drop known descriptive chunks and markers. Decline unclassified content. Preserve the exact ICC payload under a neutral PNG profile name, and preserve effective color signaling and its precedence when declarations coexist, including SDR cICP with ICC, sRGB, gamma/chromaticity and significant bits. Keep genuinely untagged files untagged. Translate an EXIF-only JPEG color declaration to a verified equivalent or decline it.

Keep pixel aspect ratio, displayed dimensions, bit depth and transparency. Keep an upright JPEG (orientation absent or 1) byte-identical in its frame and entropy-coded data; remove only metadata segments. Decline coding tables no scan uses; symbol values of unused codes inside a used Huffman table survive, because removing them would require re-encoding. For orientations 2–8, decode with the qualified decoder ignoring embedded ICC, rotate or mirror the samples, and re-encode one baseline JPEG at fixed quality 95, with 4:2:0 chroma when the source uses 2×2 chroma and 4:4:4 otherwise. A grayscale source stays one component. Write only the JFIF density, with axes swapped for orientations 5–8, and the exact source ICC payload; drop any Adobe APP14 segment. This is the one lossy exception: Review states **Re-encoded to apply rotation** for that file. Decline four-component (CMYK and YCCK) JPEGs. Preserve decoded PNG samples losslessly. Decline unreadable or non-identity PNG EXIF orientation, conflicting, duplicated or invalid orientation tags, APNG, HDR/gain maps, secondary images, motion photos, trailers after JPEG EOI or PNG IEND, and unused bytes after the zlib stream inside PNG IDAT. [PNG color and chunk rules](https://www.w3.org/TR/png-3/) · [ExifTool color guidance](https://exiftool.sourceforge.net/faq.html#Q32)

**Video.** First qualify self-contained, unencrypted, non-fragmented MP4 and MKV with one 8-bit SDR H.264 track and optional AAC-LC audio. Remux in the original container without re-encoding. Preserve coded pictures, AAC access units, timing, display transform, color, aspect ratio, audio layout, track roles and language. Remove descriptive container, track and supported codec fields including location, track names and encoder text. Zero mandatory MP4 movie, track and media creation/modification dates. Omit Matroska DateUTC. Keep required structure, supported playback fields and fixed generic muxer values. Decline AAC with opaque data or fill payloads. Decline files with video Content Credentials, including MP4 C2PA UUID boxes, until their carrier has a qualified removal path. Also decline private-use language subtags, unfamiliar auxiliary payloads, captions or subtitles, chapters, attachments, HDR, timed metadata, external references and additional tracks. [Matroska track language](https://www.rfc-editor.org/rfc/rfc9559.html#section-5.1.4.1.20) · [MP4 movie header](https://developer.apple.com/documentation/quicktime-file-format/movie_header_atom)

## Tools and release checks

Use maintained local tools. Qualify exact versions on the supported platforms and check distribution terms before packaging. Sharp provides bounded decoding for verification. TypeScript removes JPEG markers, writes JPEG metadata and applies the PNG chunk allowlist. Sharp decodes, orients and re-encodes rotated JPEGs under [D7](decisions.md#d7--prepare-local-images-in-process). ExifTool can provide independent inspection. For video, evaluate FFmpeg and MKVToolNix. A Linux probe found H.264 encoder text after stream copying and a regional language tag lost by FFmpeg but invisible to ffprobe. [FFmpeg bitstream filters](https://ffmpeg.org/ffmpeg-bitstream-filters.html#filter_005funits) · [mkvmerge](https://mkvtoolnix.download/doc/mkvmerge.html)

- Use synthetic files and a recording upload adapter. Verify the original checksum and zero external calls through Review. Check that Review explains public-link access before any upload has issued a URL. Change only the access or retention terms and prove that the old authorization sends zero bytes. An operation whose provider documents no support for the cleaned format must also send zero bytes. Test direct bypass, changed file/order, missing consent, replay, expiry and failure. Compare the received bytes with the reviewed copy and verify the neutral filename. Test a disallowed upload destination or redirect and verify that it receives neither the cleaned file nor credentials. Check logs, database and persistent browser storage for source markers and upload URLs.
- Independently inspect structure and fully decode results. Place markers in compressed and nested descriptive fields, thumbnails, C2PA, IPTC AI-source tags, track names, dates and recognized H.264 encoder text. Require successful removal. Use separate declined fixtures for unknown chunks, unused IDAT bytes, trailers, secondary images, HDR, opaque AAC data/fill and video Content Credentials. For each declined category verify the fixed reason, recovery advice, zero uploads and zero billable submissions.
- Compare exact ICC bytes including planted creator, copyright, date and description fields, competing cICP/ICC and gamma-only declarations, EXIF-only color, untagged files, aspect ratio, 16-bit PNG samples, JPEG coefficients and rotated/mirrored appearance. Check odd-dimension JPEG rotations and flips, invalid or conflicting orientation, non-identity PNG orientation and APNG refusal. For each video container compare normalized coded picture payloads and exact AAC access units across remux, decoded presentation, timing through the last frame, A/V sync and track properties. Exercise standard regional language and private-use tags.
- **Preparation lifetime.** Image preparation runs in the server process with no helper. One preparation at a time per installation, across formats; it takes its slot before reading the body and holds it until all work, including sharp's thread pool and the staged write, settles. 30 seconds each, within sharp's pixel limit, no operation cache. Shutdown stops admission, awaits settlement, then closes storage. A later format's native helper needs OS-enforced parent-death kill, CPU and address-space ceilings and an external deadline; after restart, nothing is admitted while an earlier helper could run.
- **Shared scratch.** Every staged copy, of any kind, reserves space in one private 128 MiB pool per installation, stored under `<data>/scratch/<kind>/` (upper bound first, then the actual size) and keeps it until its file is deleted. Dispatch buffers have a separate 32,000,000-byte quota. Startup reclaims scratch only under the installation lock.
- Set finite limits for encoded and decoded sizes, decompressed metadata, execution time, memory and scratch space before enabling a format or provider route. Test oversized compressed chunks and profiles, cancellation, disconnect, timeout and restart. Verify temporary cleanup after success and failure on Linux and macOS, including Unicode filenames and spaces.
