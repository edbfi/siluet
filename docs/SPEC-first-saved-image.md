# First saved image

**Milestone 3, first slice · Approved by the owner.** The creator queues one reviewed Seedream 5.5 text-to-image generation on either connected provider, follows it in Jobs, and Siluet saves it automatically. The creator opens the saved image after restarting Siluet with both providers offline. Live Queue supports one request and zero retries. The [single-reference edit](SPEC-seedream-reference-edit.md) extends this flow to one URL and the [multi-reference edit](SPEC-seedream-multi-reference-edit.md) supports up to ten in order. Files, batches and automatic retries retain [offline Review](SPEC-image-studio.md) with an explanation beside the disabled Queue.

## What one click authorizes

Queue requires a signed-in owner and a same-origin POST. Review displays the provider, one potentially billable submission, and a dated price estimate or its specific unknown-cost reason. Queueing at an unknown price requires explicit acceptance of that uncertainty. For ToAPIs, show the standard-route estimate and require this acceptance whenever an unpriced fallback is possible, including when eligibility is unknown. Bind the route disclosure and acceptance to this Review and clear acceptance when the reviewed terms change. The server issues an opaque review identifier bound to the owner, canonical validated inputs, provider and credential revision, attempt limit, and the quote the creator actually saw (including rate evidence, expiry and unknown reason). Use an installation-keyed digest where a binding survives restart. Keep the prompt transient. Editing the draft requires a new Review.

On first use, verify that binding against the submitted request and recompute eligibility and the quote with the current local clock and feeds. Poyo.ai requires a readable key accepted by the balance check and a supported model. ToAPIs also requires Seedream in the key's accessible image models. Recheck locally. A changed price, unknown reason, connection or other material input returns an updated Review for a new click before any provider call. Enforce the same limits on direct requests.

In one Turso write transaction, check that the reviewed credential revision is still current and eligible, claim the identifier for one job, and reserve its sole attempt. This commit authorizes dispatch. If removal or replacement commits first, return to Review with zero provider calls. If the claim commits first, that one attempt may use the reviewed key even if Settings changes immediately afterward. Concurrent or later replay of the identical bound request returns the original job, including after restart or a subsequent price or key change. Reject mismatched reuse. Neither replay path contacts a provider. Send only the approved payload with its reviewed key. Record a valid provider task ID durably on receipt. The local identifier provides no provider-side retry guarantee.

A documented, unambiguous validation, authentication, quota or filtering rejection ends the attempt with a safe explanation. A timeout, upstream error, ambiguous body, or restart with a claimed attempt and no durable outcome becomes **May have been submitted**. This includes a crash between provider acceptance and recording the ID. Never resend automatically. Explain that the first attempt may still cost credits and direct the creator to provider history before they explicitly review and authorize a new attempt.

## Jobs and billing

Poll an acknowledged task with its original credential revision. Multiple tabs share one tracking operation. Resume outstanding reads after restart within the existing polling window. Settings warns before key removal or replacement when jobs still need the key. Jobs explains why a changed key pauses status and retrieval of unsaved results. Keep the last known state on a read error. Pause on authorization errors, a missing task or an unknown status. Only an explicit failed task status confirms generation failure after acknowledgement. Temporary read failures use exponential backoff and honor a longer Retry-After. After two minutes of automatic tracking, stop issuing reads and offer **Refresh status** on the same task. Persist this deadline across restart. Automatic polling, manual Refresh and Retry download share the same per-task status-read limit across tabs. Coalesce simultaneous reads and preserve the next permitted read time across restart, including any outstanding Retry-After. During a cooldown, show when the owner can try again and issue zero status requests.

Keep the accepted estimate separate from charges and wallet activity. For Poyo.ai, compare a before-submit balance with one after a confirmed terminal outcome on the same credential revision. Discard account details, including email. An unavailable before-read permits the authorized submission; withhold the comparison for missing readings, overlap or uncertain outcome. ToAPIs model credentials authorize no wallet read in this slice. [Poyo.ai balance contract](https://docs.poyo.ai/api-manual/account-management/user-balance)

## Save, reopen and remove

Siluet downloads a completed result into Gallery without a click ([D9](decisions.md#d9--save-automatically)). Jobs shows **Waiting to download**, **Saving to Gallery**, **Saved** with a link, **Download failed** with **Retry download**, **Removed** or **File missing** with **Download again** while the provider link is valid, or the read pause that stops it. Retry reads the same task and never submits. Every available Gallery tile and the opened item offer **Download**, an ordinary browser download named with a short job id. Keep signed result URLs in server memory and obtain them from the acknowledged task. Save downloads the single image from a public HTTPS destination supplied by the provider. Check the actual resolved address used for each connection, including redirects; reject local or private destinations. Media requests carry no API authorization, cookies or user-supplied destination or filename. Enforce a 30-second total transfer deadline, 32 MiB encoded limit and a decoded image limit of 16 megapixels with a 16,384-pixel maximum edge. Verify the bytes decode as PNG or JPEG before publication.

Write under an application-generated name in the private installation directory. Publish one Gallery entry per result only after the complete file is durable. Concurrent saves and restarts recover or clean up partial files and unindexed writes. An expired link, invalid image, failed download or full disk leaves the generation outcome visible. A failed download is retried automatically up to three times. Retry download only queries the same task and retries the download.

Only the owner can list, open and download local images. Serve verified media types with private, no-store caching and nosniff. A missing file is marked unavailable. Gallery works after credential removal and without provider traffic. The owner can confirm **Remove from Gallery** to delete the local file and entry; recover interrupted deletion on restart. Removing an image retains the job history and never changes the remote task.

Retain minimal job and attempt history for the lifetime of the installation, including task ID, provider, credential revision, model, timestamps, last known state, accepted quote, available billing evidence and local media reference. Saved images have no automatic expiry. Keep prompts, keys, full result URLs, filesystem paths, raw responses and media bytes out of logs, diagnostics and browser storage. Use bounded, mapped error descriptions so provider echoes cannot expose private inputs.

## Acceptance

Use the built Bun app and fixture providers. Route traffic to loopback only in the test harness. Run the [development checks](../README.md#development) and verify the following with keyboard and narrow-screen coverage.

- For both providers, Queue, follow the job until it is saved without a click, restart, disconnect the provider and reopen the original image bytes offline. Remove the image, restart and verify both file and entry are gone.
- Reject signed-out or cross-origin mutations, out-of-scope direct requests, tampered bindings and mismatched replay. With changed or expired prices or credentials, require fresh Review with zero provider calls. Test missing and explicit acceptance of an unknown price, including a known ToAPIs standard rate with an unpriced fallback. Race Queue against key removal or replacement in both commit orders and verify the corresponding provider call counts. Simultaneous and later identical replays return one job and one total generation POST.
- Stop the process after claim before dispatch (zero POSTs), and again after fixture acceptance before recording the ID (one POST). Recover both as uncertain without another POST. With a durable ID, recover through reads alone. Exercise a Poyo.ai HTTP-200 validation rejection, upstream timeout, 401/403/404 status reads, unknown states, throttling, exhausted polling window, and key replacement. Click Refresh and Retry download from separate tabs during a persisted cooldown and assert zero status reads until it ends.
- Check provider credit and settlement labels, ToAPIs pending, missing and refunded billing, and missing or overlapping Poyo.ai wallet readings. Plant sentinel account data, prompts, keys and URLs and check their exclusion from diagnostics and persistent storage as specified.
- Verify default download policy, rejected unsafe redirects and absent authorization at the media host. Exercise invalid, oversized and expired results, interrupted Save and Remove, Retry download, Download again and a missing file. Count provider generation POSTs throughout recovery. Automated checks use fixtures; a live billable test requires separate express approval.
